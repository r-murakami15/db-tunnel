# 4. セキュリティ設計

[目次に戻る](README.md)

設定ファイルだけが漏れても中身を読めないよう、暗号化の鍵はファイルと別の場所（OSのキーチェーン）に置く。DBのパスワードはそもそも保存しない。

## 4.1 暗号化と鍵の管理

- 初回起動時に32バイトのランダムな鍵を生成し、OSのキーチェーンに保存する（`keyring` クレート）。
  - Windows: 資格情報マネージャー（DPAPIで保護され、ログインユーザーしか読めない）
  - Mac: ログインキーチェーン
- 設定ファイルはこの鍵でAES-256-GCMにより暗号化する。改ざんされた場合は認証タグの検証で検知し、読み込みを中止する。
- 鍵はメモリ上で使い終わったら `zeroize` で消す。
- 鍵が見つからない、または復号に失敗した場合は、設定ファイルを `config.enc.broken-<日時>` に退避し、空の状態で起動する。利用者には「JSONを再インポートしてください」と案内する。

設定ファイルの保存場所と構造は [3.3 アプリの設定ファイル](02-data-design.md#33-アプリの設定ファイル) を参照。

## 4.2 守れるもの・守れないもの

| 状況 | 結果 |
| --- | --- |
| 設定ファイルだけが外部に漏れた | 鍵がないため読めない |
| 別のユーザー・別のPCで設定ファイルを開いた | キーチェーンが別なので読めない |
| 設定ファイルが改ざんされた | 復号時に検知して読み込まない |
| 本人のPCにログインした状態で、マルウェアが本人の権限で動いた | 守れない（キーチェーンから鍵を読めるため） |
| エクスポートしたJSON | 平文。秘密情報は含まない前提で許容する |

なお、設定ファイルに入るのは接続先の名前・プロファイル名・環境・アプリ名・ポートで、パスワードやAWSの認証情報は入らない。

## 4.3 秘密情報の扱い

- DBのユーザー名とパスワードは接続のたびにSecrets Managerから取得し、メモリ上にのみ置く。停止時に消す。
- AWSの認証情報はアプリで扱わない。`aws login` が作るCLIのキャッシュをそのまま使う。
- ログはメモリ上のみで、利用者が「保存」を押したときだけファイルに書く。パスワードはログに出さない。
- パスワードのコピーは30秒後にクリップボードから消す。
- 外部への通信はAWS CLI経由のAWS API呼び出しとアップデート確認のみとし、利用状況の送信などはしない。

## 4.4 Macで署名しないことの影響

キーチェーンの項目は、作成したアプリの署名に結びつく。署名なしのアプリはビルドごとに識別情報が変わるため、アップデート後の初回起動で「キーチェーンへのアクセスを許可しますか」と聞かれる。「常に許可」を押せば以後は聞かれない。この点は配布時の手順書に記載する（[8章](07-build-and-release.md#84-初回インストール手順利用者向け手順書に記載)）。
